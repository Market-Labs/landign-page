# User Stories

## US01: View Product Value Proposition

**As a** visitor,  
**I want to** understand clearly what MarketGo is, what problem it solves, and what value it provides,  
**so that** I can quickly determine whether MarketGo is a suitable solution for my needs.

### Description

The landing page should communicate the main value proposition of MarketGo in a simple and understandable way. The visitor should be able to identify what MarketGo offers without having to navigate through multiple pages.

The main section of the landing page should present a clear headline, a brief description of the product or service, and a relevant call-to-action.

### Acceptance Criteria

- [ ] The landing page displays a clear and concise headline describing MarketGo.
- [ ] The visitor can understand the main purpose of MarketGo without additional navigation.
- [ ] The page explains the main problem or need that MarketGo addresses.
- [ ] The value proposition is visible in the first section of the landing page.
- [ ] A clear call-to-action is available for the visitor to continue exploring or contact the team.
- [ ] The content is understandable for users who are not familiar with MarketGo.

---

## US02: Explore Services and Benefits

**As a** visitor,  
**I want to** explore the main services, features, and benefits offered by MarketGo,  
**so that** I can understand how the solution can help me and compare its benefits with my current needs.

### Description

The landing page should provide an overview of the most important services or features offered by MarketGo. Information should be organized into easily scannable sections so that visitors can quickly understand what they receive from the solution.

Each service or feature should communicate not only what MarketGo provides, but also the benefit it offers to the customer.

### Acceptance Criteria

- [ ] The landing page contains a dedicated section for MarketGo's main services or features.
- [ ] Each service has a clear title and description.
- [ ] The benefits of each service are explained from the customer's perspective.
- [ ] The information is organized into visually distinguishable sections or cards.
- [ ] The content allows users to quickly scan and compare the different services.
- [ ] The section includes relevant visual elements when necessary to improve comprehension.
- [ ] The information is responsive and readable on desktop and mobile devices.

---

## US03: Review Plans

**As a** visitor,  
**I want to** review the available MarketGo plans, their features, and their pricing or conditions,  
**so that** I can identify which option best matches my requirements and decide what action to take next.

### Description

The landing page should provide enough information about the available plans for visitors to understand the differences between them. Each plan should clearly communicate what is included and what type of customer or need it is intended for.

The plans should be presented in a consistent format to make comparison easier.

### Acceptance Criteria

- [ ] The landing page contains a dedicated plans or pricing section.
- [ ] All available plans are displayed clearly.
- [ ] Each plan includes its name and relevant price or pricing information.
- [ ] Each plan lists its main features or benefits.
- [ ] Differences between plans are easy to identify.
- [ ] Each plan includes a clear call-to-action.
- [ ] The visitor can understand what they receive with each plan without needing to contact the team first.
- [ ] The plans section is responsive and usable on mobile devices.

---

## US04: Contact the Team

**As a** potential customer,  
**I want to** submit my contact information and a message to the MarketGo team,  
**so that** I can request more information, ask questions, or receive assistance choosing a plan.

### Description

The landing page should provide an easy-to-use contact form that allows potential customers to communicate with the MarketGo team. The form should request only the information necessary to establish contact and understand the visitor's request.

The user should receive clear feedback after submitting the form.

### Acceptance Criteria

- [ ] The landing page contains a visible contact section.
- [ ] The contact form includes the necessary fields:
  - [ ] Name
  - [ ] Email
  - [ ] Phone number, if required
  - [ ] Message or inquiry
- [ ] Required fields are clearly identified.
- [ ] The form validates required fields before submission.
- [ ] The email field validates that the entered value has a valid email format.
- [ ] The user receives a clear validation message when required information is missing or invalid.
- [ ] After a successful submission, the user receives confirmation that the request was sent.
- [ ] The form prevents accidental submission when required information is incomplete.
- [ ] The form is responsive and usable on desktop and mobile devices.
